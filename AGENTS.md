# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project

**Vocalis** — a local-first, realtime speech app for macOS (STT, TTS, voice cloning) built on Tauri v2 + Rust + React 19, with sherpa-onnx running in-process in Rust. Planning docs live in `spec/`: `spec/spec.md` is the authoritative product/technical spec (features, architecture, decision record) — consult it before designing anything new; `spec/current_plan.md` is the current status snapshot + next actions; `spec/M0.md`–`spec/M5.md` are the detailed per-milestone implementation plans. `inspiration.md` documents the Sapio codebase this app reuses patterns from; `spike-zipvoice.md` records the ZipVoice cloning spike verdict (GO, ~0.8 s time-to-first-audio at 8 threads, no French).

## Commands

Package manager is **bun**.

```sh
bun run desktop:dev    # full app (tauri dev — required for anything touching audio/engines)
bun run dev            # webview only in a browser (vite, port 3002); all Tauri calls are no-ops
bun run build          # vite build (also what tauri bundles)
bun run desktop:build  # production .app bundle
bun run check-types    # tsc --noEmit
bun run lint           # biome check .   (lint only — formatter is disabled)
bun run lint:fix       # biome check --write .
bun run test           # vitest watch
bun run test:run       # vitest run (CI mode)
bunx vitest run src/lib/tree-utils.test.ts   # single test file
```

Rust (from `src-tauri/`):

```sh
cargo check
cargo test                                        # unit tests
cargo test --test engines_integration -- --ignored  # integration tests; need real models in ~/.vocalis/models/
```

## Architecture

Two halves, one strict boundary:

- **Webview** (`src/`): React 19, TanStack Router file-based routes, Zustand stores, Tailwind v4 + shadcn/ui, Zod schemas.
- **Rust** (`src-tauri/src/`): audio capture, all local speech engines (sherpa-onnx), pipelines, model registry, fs/config/keychain/logging commands.

**The IPC rule (spec §3.2): raw audio never crosses the Tauri boundary during realtime capture.** Audio stays in Rust; the webview receives only serialized `PipelineEvent`s over a Tauri `Channel` (`Partial`, `Final`, `VadState`, `Error`, …). File-based operations pass paths, not bytes. TTS returns a wav file path, played in the webview via `convertFileSrc` (see `src/lib/engines/local.ts`, the sole TS↔Rust speech bridge).

### Rust side (`src-tauri/src/`)

- `commands/` — Tauri commands grouped by domain (fs, config, keychain, logging, speech, app); every new command must be registered in `lib.rs`'s `generate_handler!`.
- `engines/` — one module per sherpa-onnx task (`asr_streaming`, `vad`, `tts`). New engines follow this shape and get lazily loaded/cached in `state.rs`'s `SpeechState` (the EngineManager).
- `pipeline/` — each running pipeline is a dedicated OS thread owning its cpal capture + engine sessions, stoppable via an `AtomicBool` in `PipelineRegistry`. Commands: `asr_pipeline_start` (returns id immediately; readiness/errors arrive as events) / `asr_pipeline_stop`.
- `audio/` — cpal capture, resample to 16 kHz mono f32.
- `registry/` — resolves models from `~/.vocalis/models/<task>/<modelId>/`; `first_installed(task)` is the fallback when config names no model.

### Webview side (`src/`)

- `routes/` — one file per icon-bar section (chat, playground, voices, models, settings, debug). `routeTree.gen.ts` is generated by the router plugin — never edit it. Adding a section = new route file + extend `navItems`/`SectionId` in `components/layout/sidebar.tsx`.
- `stores/` — Zustand; `settings-store` writes API keys through to the macOS keychain (service `Vocalis`) and excludes them from persistence under Tauri.
- `lib/config-sync.ts` — two-way sync between the settings store and `~/.vocalis/config.yaml`: debounced 500 ms writes, 2 s file poll, `isPatchingFromFile` loop guard. It preserves file fields the store doesn't own — extend `extractConfigFromStore` when adding synced settings.
- `lib/storage.ts` — all fs access goes through Tauri commands, guarded by `isDesktop()`; in a plain browser (and in vitest) every call is a no-op returning empty values. Code must tolerate this.
- `lib/schemas/` — Zod schemas; all machine state on disk is JSON validated at load (config.yaml is the only YAML, because it's human-edited).

### Storage & data

Everything lives under `~/.vocalis/` (spec §4): `config.yaml`, `models/<task>/<id>/`, `logs/`, `cache/tts/`, etc. Audio convention: 16 kHz mono FLAC. API keys only in the keychain, never in files.

## Conventions

- Tests are colocated (`foo.test.ts` next to `foo.ts`), run under jsdom with `src/test/setup.ts`; Tauri APIs are mocked via `src/test/mocks/tauri.ts`.
- Biome ignores `components/ui/` (shadcn vendored code) and `routeTree.gen.ts` — don't hand-fix lint issues there.
- Path alias `@` → `src/` (vite + vitest + tsconfig).
- Engine routing (spec §3.4): every speech task resolves through per-task defaults + inline overrides + a global privacy mode that hard-filters API engines. Never add a silent local→API fallback.
- No god files — Sapio's 733-line settings view is the explicitly flagged anti-pattern; split by domain (see `commands/` modules vs. a single `commands.rs`).
