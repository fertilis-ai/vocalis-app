## 3. Voice turn pipeline ✅ code-complete (2026-07-11)

- **Capture (Rust):** new `src-tauri/src/pipeline/chat_capture.rs`, same thread-owning shape as dictation: VAD (configurable silence threshold, default ~800 ms, from Voice Chat settings) → streaming ASR partials → endpoint finalizes the turn. Commands `chat_capture_start(config) -> channel` / `chat_capture_stop(id)`; events `Partial` (rendered live in the composer), `Final` (submits the turn), `VadState`. Continuous listening: after a final, the pipeline keeps running for the next turn.
- **Reply path (webview):** LLM streams → `src/lib/audio/sentence-chunker.ts` (split on sentence boundaries as deltas arrive; flush on stream end; unit-test edge cases: abbreviations, numbers, code blocks — skip code blocks for speech) → per-sentence `tts_synthesize` with a small look-ahead queue (synthesize sentence N+1 while N plays) → `src/lib/audio/playback-queue.ts` (ordered, cancelable, single active).
- **Playback state reporting:** the queue reports play/stop to Rust via a `chat_capture_set_playback(id, active)` command so the capture pipeline can **pause mic capture into VAD/ASR during playback** (echo mitigation, spec §3.2/§7.4).

**Build record:** `src/lib/audio/use-voice-chat.ts` orchestrates capture → LLM turn → sentence-chunked TTS playback, driven by `startChatCapture`/`stopChatCapture`/`setChatCapturePlayback`/`forceFinalizeChatCapture` wrappers in `src/lib/engines/local.ts`. `voice-chat-bar.tsx` replaces the composer while voice mode is active (live status, partial transcript, hold-to-talk button, stop). `chat-view.tsx` wires it in with a hands-free/push-to-talk mode switcher and a read-only `EngineChip` for the streaming ASR engine; the pre-existing auto-read-aloud effect is guarded off while voice chat is active to avoid double-playing replies.

## 4. Turn-taking, barge-in, and modes ✅ code-complete (2026-07-11)

- **Playback pause (supersedes barge-in):** mic capture is fully paused in Rust for the whole span of a TTS reply (queue-level, not per-sentence) and resumes once playback drains. There is no barge-in — the pipeline emits no `VadState` events while paused, in either hands-free or push-to-talk mode, so a reply can only be interrupted by waiting for it to finish. The Voice Chat settings barge-in checkbox is disabled/informational as a consequence (see below).
- **Echo mitigation v1:** playback pause (above) + a "use headphones for conversation mode" onboarding hint. AEC is v2 (spec §7.4) — do not build it now.
- **Push-to-talk alternative:** per-conversation input mode; hold-to-talk uses the same capture pipeline gated by key state instead of VAD endpointing. Holding the key during a TTS reply captures nothing, same as hands-free mode.
- **Per-conversation pickers:** voice (from the TTS voice library — stock/provider voices now; clones join in M5) and model (pi-ai discovery). **Transcript-only mode** = mute TTS toggle per conversation.
- **Voice Chat settings section:** VAD silence threshold, barge-in (disabled, informational only), default voice/model.
- EngineChip appears on the chat surface for the STT engine (streaming ASR routes through the router; FR default is Deepgram per the routing matrix — works only if the M2 Deepgram streaming adapter landed, otherwise local-only until then).

**Build record:**
- **Playback pause** replaced an earlier VAD-threshold-boost approach: the capture pipeline now holds a single VAD detector and simply stops pushing samples into it (and into the utterance buffer) while `playback_active`, resetting the detector on every pause/resume transition. This makes barge-in permanently unreachable by construction (no `VadState` events fire while paused) rather than gated by the `bargeInEnabled` setting — that field stays in the schema/store (no migration) but its checkbox is now disabled/informational in Settings.
- **Push-to-talk:** since `chat_capture_force_finalize` resolves asynchronously via the same `Final` event as natural VAD endpointing (fire-and-forget, unlike `dictation_finalize`'s synchronous return), `use-voice-chat.ts` accumulates `Final` text in a ref while the key is held and only submits on release, with a 400 ms fallback flush (generation-counted) in case no trailing `Final` arrives.
- **Transcript-only mode** reuses the existing `conversation.ttsEnabled` field — no new schema field; when false, the sentence chunker/playback queue are simply never fed.
- **Voice Chat settings** (`src/components/settings/voice-chat-settings.tsx`, new "Voice Chat" section between Chat and Dictation): VAD silence-threshold range input (300–2000 ms, plumbed through `chat_capture_start`'s new `min_silence: Option<f32>` param to `VadParams.min_silence` in `src-tauri/src/commands/chat_capture.rs`), a disabled/informational barge-in checkbox (superseded by playback pause), default voice/model pickers (reusing `VoicePicker`/`ModelPicker`). Backed by `VoiceChatPrefs` in `settings-store.ts`, `voiceChatSchema`/`DEFAULT_VOICE_CHAT` in `schemas/config.ts`, two-way synced in `config-sync.ts`. New conversations (`chat-sidebar.tsx`'s `createChatLeaf`) prefill `voiceId`/`modelRef` from the defaults.
- **EngineChip** is read-only (`<EngineChip task="streamingAsr" />`, no `onOverride`) — safe because `deepgram.nova`'s `implemented: false` keeps it permanently ineligible, so the chip can never claim an engine that isn't actually running.

## Rules

- Raw mic audio stays in Rust; the webview receives only events. TTS returns wav paths played via `convertFileSrc`.
- Never a silent engine fallback; the chip always shows what's live.
- Verification per change: `cargo check`, `cargo test`, `bun run check-types`, `bun run test:run`, `bun run lint`. Unit-test the sentence chunker and playback queue thoroughly (they're pure TS).
- Exit test is human and on-device with headphones **and** speakers: multi-turn hands-free conversation (plus a push-to-talk pass), talk over the assistant's reply through speakers at least three times and confirm it's never transcribed back as a spurious turn (no echo loops), and confirm capture resumes promptly once each reply finishes. Record results in `current_plan.md`.
