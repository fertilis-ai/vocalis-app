## 2. ZipVoice local synthesis ✅ code-complete (2026-07-16)

**Build record.**
- **Engine** (`src-tauri/src/engines/tts_zipvoice.rs`): `CloneTtsEngine` on the official crate's `OfflineTtsZipvoiceModelConfig` — no FFI needed. Gotcha found and handled: the crate's `Default` zeroes the ZipVoice hyperparameters, so the C++ defaults are set explicitly (`feat_scale 0.1, t_shift 0.5, target_rms 0.1, guidance_scale 1.0` — verified against sherpa-onnx v1.13.4 source). `synthesize_to_wav(text, ref_samples, ref_rate, ref_text, speed, num_steps, out)`; `num_steps` defaults 4 (spike A/B). Separate engine struct, not a `TtsEngine` branch — the layouts share nothing.
- **State** (`state.rs`): `CloneTtsSlot {model_dir, num_threads, engine}` + registered in `model_in_use`. Unlike other slots it is **evictable**: `clone_tts_unload` drops it (~600 MB resident), `clone_tts_warm` pre-loads and returns load ms — the spec §3.3 "warming up" surface (the webview awaits it and shows its own state; TTS commands stay blocking rather than channel-based).
- **Command** (`commands/speech.rs`): `clone_tts_synthesize(text, ref_audio, ref_text, model?, speed?, num_steps?, num_threads?, max_cache_bytes?)` → `CloneTtsResult {path, durationSecs, cached, engineLoadMs, synthMs}` for TTFA metrics. Threads default `(cores − 4).clamp(4, 8)` (spike §risks.3), overridable per call. Content-addressed cache in the shared `cache/tts` LRU, keyed on model+text+refPath+**ref mtime+size**+refText+speed+steps so re-recording a reference never replays the old voice. Tilde-expands `ref_audio` (webview passes `~/.vocalis/people/…`). Errors surface; never reroutes to an API engine.
- **TS bridge** (`src/lib/engines/local.ts`): `cloneTtsSynthesize`/`cloneTtsWarm`/`cloneTtsUnload` + `startCloneRefRecording`/`cloneRefQuality`. Descriptor `local.zipvoice` flipped to `implemented: true`, langs `["en", "zh"]` (**no French** — spec §7.1).
- **Test**: `zipvoice_clones_from_reference` (`--ignored`, real model) passes — synthesizes English from the bundled zh reference fixture: **load 0.52 s, 4.72 s audio in 1.32 s (RTF 0.28)**, on target vs the spike.
- **Chat integration** landed with item 4: clone voices flow through the M4 sentence-chunked playback queue via `synthesizeSpeech`'s clone dispatch; warm-up fires on conversation open (see item 4). On-device TTFA profiling against the < 1.5 s target belongs to the live pass.
